# Migration-Friendly Config Design

Date: 2026-05-03

## Goal

Make AITrend easy to move to a new machine:

1. `git clone` the repository.
2. Copy `.env` and `config.yaml`.
3. Run one environment setup/check command.
4. Run the pipeline.
5. On a new machine, scan login QR codes once for WeChat MP, Xiaohongshu, and Zhihu.

The target data sources are `wechat_mp`, `xiaohongshu`, and `zhihu`. The legacy Sogou WeChat source is not part of the normal migration path. Longxia automatic upload is not part of the normal path; the local Markdown report remains the final output.

## Non-Goals

- Do not make browser login state portable. Login state is machine-local and should be regenerated by QR login on each new machine.
- Do not require users to edit Python modules for normal operation.
- Do not remove legacy sources or longxia code unless needed for clarity. They should be disabled by default and documented as optional or legacy.
- Do not turn `.env` into a large structured config file.

## Configuration Model

Add a root-level `config.yaml` as the main business configuration file, plus `config.yaml.example`.

`.env` keeps secrets and machine-local values:

- `LLM_API_KEY`
- `LLM_BASE_URL`
- `LLM_MODEL`
- optional LLM timeout/retry/concurrency overrides
- optional machine paths only when a user intentionally deviates from defaults

`config.yaml` keeps structured business settings:

- enabled sources
- WeChat MP account list
- Xiaohongshu keywords and result count
- Zhihu keywords and result count
- collection time window
- top-N selection
- output directory and filename pattern
- per-source browser/login mode defaults
- local Markdown export settings

Representative shape:

```yaml
enabled_sources:
  - wechat_mp
  - xiaohongshu
  - zhihu

collection:
  initial_collect_count: 30
  time_range_hours:
    min: 0
    max: 24

selection:
  top_n: 10

wechat_mp:
  accounts:
    - 中国教育报
    - 人民教育
  max_articles_per_account: 10
  lookback_days: 7
  browser_mode: auto
  fetch_detail_page: true
  rhythm:
    slow_mo_ms: 300
    action_delay_seconds: 1.5
    article_delay_seconds: 3
    page_delay_seconds: 4
    account_delay_seconds: 8

xiaohongshu:
  keywords:
    - 教育改革
    - 中考
  max_results_per_keyword: 20
  login_type: qrcode

zhihu:
  keywords:
    - 教育改革
    - 中考
  max_results_per_keyword: 20
  login_type: qrcode

output:
  dir: ./output
  filename_pattern: 教育热点日报_{date}.md
  longxia_candidate_export_enabled: false
```

## Runtime Directories

Keep runtime state out of Git and out of the migration contract:

- `browser_data/`
- `MediaCrawler/browser_data/`
- `MediaCrawler/data/`
- `raw_data/`
- `merged_data/`
- `scored_data/`
- `output/`
- `logs/`

The application creates these directories as needed. A new machine starts without login state; the first run opens visible browser windows for QR login where needed.

## Code Architecture

Introduce a small typed configuration layer:

- `config/app_config.py`
  - Pydantic models for `config.yaml`
  - defaults matching current behavior for counts, output paths, browser rhythm, and login modes
  - validation for source names, positive counts, and valid login/browser modes
  - path resolution relative to the project root, not the shell's current directory
- `config/settings.py`
  - remains as a compatibility facade for existing imports
  - loads `.env` and `config.yaml`
  - exposes the existing constants so crawlers can be migrated incrementally

This keeps implementation risk low: existing modules can continue importing constants while the underlying source of truth moves from scattered environment parsing to typed config.

## Login Behavior

WeChat MP should use a browser mode with `auto` behavior:

- If local storage state exists, try reusing it headless if configured.
- If no valid state exists, open a visible browser and wait for QR login.
- Save the new state under `browser_data/wechat_mp_state.json`.

Xiaohongshu and Zhihu should default to `qrcode` login through MediaCrawler:

- No cookie is required in `.env`.
- On a fresh machine, MediaCrawler opens its browser flow and the user scans once.
- MediaCrawler stores its own login state under `MediaCrawler/browser_data/`.

Cookie login may remain available as an advanced option, but it is not the recommended migration path.

## Environment Setup

Add a setup/check entrypoint, `scripts/bootstrap.py`, with an explicit workflow. The script should be safe to run after creating and activating `.venv`; it should use only the Python standard library until dependencies are installed, so it can bootstrap a fresh clone.

1. Verify Python version.
2. Create required runtime directories.
3. Install root requirements with the active Python environment.
4. Install MediaCrawler requirements with the same active Python environment.
5. Run `playwright install chromium`.
6. Check Node.js availability for Zhihu/MediaCrawler JavaScript signing.
7. Check that `.env` and `config.yaml` exist.
8. Validate config and show enabled sources.
9. Report login state status without requiring it.

The command should be safe to rerun. It should not copy secrets or write login state. A `--check` mode can report missing pieces without installing anything, but the default should prepare the environment because the migration goal includes a real first-run setup.

## CLI and Docs

The default run path should stay simple:

```bash
python scripts/bootstrap.py
python main.py run
```

`python main.py search` should still work for collection-only debugging.

README should be rewritten around the new migration contract:

```bash
git clone <repo>
cd AITrend
python -m venv .venv
source .venv/bin/activate
cp /old/AITrend/.env .env
cp /old/AITrend/config.yaml config.yaml
python scripts/bootstrap.py
python main.py run
```

The docs should call `wechat` the legacy Sogou source and `wechat_mp` the fixed-account WeChat MP source to avoid future confusion.

## Error Handling

Configuration errors should fail before any crawling starts:

- missing `config.yaml`
- missing `LLM_API_KEY` for `run`
- empty account/keyword list for an enabled source
- unsupported source names
- invalid counts or time windows

Environment errors should be actionable:

- missing Node.js: tell the user it is needed for Zhihu/MediaCrawler and print the detected status
- missing MediaCrawler dependency: print the install command
- missing Playwright browser: print `playwright install chromium`
- missing login state: do not fail in bootstrap; first real run should open login flow

## Testing

Add focused tests for:

- loading `config.yaml`
- `.env` values overriding only secret/machine fields
- invalid source validation
- empty enabled-source account/keyword validation
- path resolution from project root
- longxia export disabled by config
- WeChat MP browser mode choosing visible login on missing state

Existing crawler tests should keep using mocks and temporary directories. No test should require real platform login.

## Migration Success Criteria

A clean clone is considered migration-ready when:

1. Copying `.env` and `config.yaml` restores all business settings and LLM settings.
2. `python scripts/bootstrap.py` completes or prints a short actionable missing-environment checklist.
3. `python main.py run` uses only `wechat_mp`, `xiaohongshu`, and `zhihu` by default.
4. Fresh machines open login flows instead of failing headlessly.
5. The final artifact is a local Markdown report under `output/`.
6. No normal setup step requires editing Python source files.
